## Detailed Forensic Analysis

### 1. `tests/security/phase10-security-monitoring.test.ts`

* **Observed Failures & Behavior (`vitest run tests/security/phase10-security-monitoring.test.ts`):**
  * **Test 3 (`lines 66–82` — `probes live validator health and computes consensus health summary`):**
    * Calls `new ConsensusMonitor({ rpcUrls: ['http://127.0.0.1:26677', 'http://127.0.0.1:26687'], lagThresholdBlocks: 5 }).evaluateHealth()`.
    * Both `127.0.0.1:26677` and `127.0.0.1:26687` returned `ECONNREFUSED` in direct Node `fetch` probes (`netstat -ano` empty), producing `activeValidators = 0`, `consensusHalted = true`, `healthy = false`. Assertion `expect(summary.activeValidators).toBe(2)` failed (`+0 vs 2`). Line 78 also asserts `summary.networkHeight > 5000`, tying pass criteria to an aged pre-mined local testnet.
  * **Test 5 (`lines 111–127` — `generates compliant Prometheus metrics format for telemetry scrapers`):**
    * Calls `evaluateHealth()` against `['http://127.0.0.1:26657', 'http://127.0.0.1:26667']` — which are **also `ECONNREFUSED`**.
    * Running the identical class directly under `npx tsx` (`task-55907`) proved `evaluateHealth()` returned `healthy: false, activeValidators: 0` and emitted `sovra_consensus_healthy 0`.
    * **Root cause of false PASS in Test 5:** [consensus-monitor.ts:304](file:///d:/Sovra/services/api/src/monitoring/consensus-monitor.ts#L304) emitted:
      `# HELP sovra_consensus_healthy 1 if network consensus is active and within lag threshold, 0 otherwise`
      Because that `# HELP` comment literally contains the substring `'sovra_consensus_healthy 1'`, [phase10-security-monitoring.test.ts:122](file:///d:/Sovra/tests/security/phase10-security-monitoring.test.ts#L122) (`expect(metrics).toContain('sovra_consensus_healthy 1')`) matched the `# HELP` line instead of the metric value line (`sovra_consensus_healthy 0`).
* **Verified Product Defects Found in [services/api/src/monitoring/consensus-monitor.ts](file:///d:/Sovra/services/api/src/monitoring/consensus-monitor.ts):**
  1. **Zero-validator fail-open (`lines 195–197, 281`):** When `rpcUrls` is `[]` (`totalCount = 0`), `Math.ceil((2 / 3) * 0)` is `0`, `0 < 0` is `false`, so `consensusHalted = false` and `healthy = true`.
  2. **Hardcoded synthetic supply fallback (`lines 264–278`):** When `activeCount === 0` (`primaryResponsive` is `undefined`) or `/query/supply` fails, `evaluateHealth()` emits hardcoded `totalSupplyUsov: '30139348240070'` and `masterInvariantHolds: true` instead of fail-closed `'0'` / `false`. (Verified `30139348240070` exists nowhere else in the codebase.)
  3. **Prometheus `# HELP` substring collision (`line 304`):** Help comment contains metric+value pattern `'sovra_consensus_healthy 1'`.
