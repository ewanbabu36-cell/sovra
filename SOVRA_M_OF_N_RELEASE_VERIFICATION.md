## Finding-by-Finding Remediation Record

### REL-P6-01 — Eliminating Metadata-Only `builderAttestations` Acceptance (`REL-02`)
- **Original Finding & Severity:** `REL-02` (**High**) — `ReproducibleBuildProvenance.builderAttestations` previously stored unverified plain `string[]` metadata inside the maintainer signature without verifying builder Ed25519 signatures, builder key identity, or digest/commit consistency.
- **Exact Source File & Line:** [software-update.ts:20-55, 130-315](file:///d:/Sovra/packages/crypto/src/software-update.ts#L20-L55), [release-updater.ts:20-27, 170-180](file:///d:/Sovra/apps/sovra-mobile/src/services/release-updater.ts#L20-L27).
- **Root Cause:** No signed provenance object type or Ed25519 signature validation existed for individual reproducible-build builders.
- **Code Change:** Added `SignedBuilderAttestation` (`builderPubKeyHex`, `sourceCommitHex`, `buildRecipeHashHex`, `artifactSha256Hex`, `byteLength`, `builtAt`, `signatureHex`), `signBuilderAttestation()` (`SOVRA-BUILD-ATTEST-v1`), and `verifyBuilderProvenanceAttestations()`. Explicitly skips plain string entries so metadata-only strings never populate `validBuilders`; fails closed on invalid signatures, commit/recipe mismatches, digest mismatches, revoked builder keys, or unmet `minimumBuilderAttestations`. Updated `verifySignedSoftwareRelease()` and `verifyAndDownloadUpdate()` to propagate `validBuilders`.
- **Tests Executed (`task-57880`):** `tests/security/zero-domain-full-parity.test.ts` (Tests 4, 9, 12) + `packages/crypto/test/*` (9 files) + `tests/integration/founder-disappears-and-adversarial.test.ts` + `packages/protocol/test/cbor-sovra-evt-nodedb.test.ts`.
- **Actual Output:** Metadata-only strings rejected (`valid: false, validBuilders: []`); tampered builder signature rejected; revoked self-voting signer rotation rejected (`valid: false`); full 2-of-3 maintainer + 2-of-2 builder release verified bit-for-bit (`80 / 80 PASS`).

### REL-P6-02 — Live Mirror Binary Hosting & Streaming (`/api/releases/:version/artifact`)
- **Original Finding & Severity:** `REL-02` (**Medium**) — Server routes previously stored JSON manifests on `/api/releases/publish` without persisting or serving verified binary bytes for `/api/releases/:version/artifact`, forcing `release-updater.ts` verification to rely on mocked `fetcher` callbacks.
- **Exact Source File & Line:** [enterprise-protocol.routes.ts:901-998](file:///d:/Sovra/scripts/routes/enterprise-protocol.routes.ts#L901-L998).
- **Code Change:** Extended `POST /api/releases/publish` to accept `artifactBase64` (verified before disk write via `verifySignedSoftwareRelease(..., artifactBytes)`) alongside `trustedBuilderPubKeysHex` / `minimumBuilderAttestations`, and added `GET /api/releases/:version/artifact` streaming verified `application/octet-stream` binary bytes.
- **Tests Executed:** `tests/security/zero-domain-full-parity.test.ts` (Test 12 live loopback mirror server without mocked `fetcher`).
- **Actual Output:** Live HTTP mirror publish returned `200 { artifactHosted: true, validBuilders: [2 keys] }`; `verifyAndDownloadUpdate({ mirrorBaseUrls: [mirrorBase], policy })` failed over past unavailable `ipfs://` mirror, fetched binary from `/api/releases/3.0.0/artifact`, and matched bytes + `validBuilders.length === 2` + `validSigners.length === 2`.
